Public-document source plan for Compache traces

Research checked: 2026-11-17. This is a source-selection and trace-design recommendation, not a claim that public benchmark outputs have been measured in Compache.

Recommendation

For a reusable Compache trace generator that may ship in a package or be used commercially, use QASPER as the default public document/question source, with MuSiQue as the controlled AND-hop complement and LongMemEval-S cleaned as a separate conversational-memory diagnostic. QASPER provides full-text NLP papers, information-seeking questions, answer variants, unanswerable labels, and annotated evidence paragraphs/figures/tables. Its dataset card identifies CC BY 4.0. Still retain per-source provenance for the S2ORC-extracted papers and check the license/redistribution terms of the exact pinned artifacts; the repository code license does not automatically settle rights in every paper.

The 15–50k requirement is retrieval payload per run, not a requirement that one source document have that length. Measure the actual assembled payload with the target model tokenizer. QASPER's official task asks about a single paper; its usual source paper may not fill that band. Keep the official single-paper benchmark task and its answer/evidence labels intact. If an authored trace explicitly asks for a cross-paper comparison, build a faithful within-domain bundle of actual related papers and add independently curated answer/evidence labels for that new task. Do not append unrelated papers or padding to inflate context, and do not reuse the original QASPER answer as gold for a rewritten multi-document question. Report runs below the payload band separately rather than treating them as failure.

Use MuSiQue as an AND-dependency check because its 2–4-hop questions were constructed from connected single-hop questions where one step critically relies on another; its support paragraphs and sufficiency labels make the dependency structure testable. It uses short Wikipedia contexts and is not the source for long-document payload trials. Use LongMemEval-S separately for memory behaviors such as multi-session reasoning, temporal reasoning, knowledge updates, and abstention; it is a constructed conversation-history benchmark, not real business chat or source-document QA.

Keep MMLongBench-Doc-V2 as an opt-in research-only long-PDF stress set. It is the strongest candidate among those reviewed for a single document near the desired payload scale (original mean 21,214 text tokens), but the original project reports CC-BY-NC-4.0 research-use terms, and V2 is an independent corrected annotation release rather than the original authors' release. It is therefore not an unconditional default for package users or commercial use. RAGBench is a useful complementary grounded-RAG control: its 12 subsets package questions, retrieved passages, responses, and support/adherence signals, though the mixed component provenance and rights require review. It can inform a response-grounding check, not replace the selected full-text source corpus. FinanceBench remains a finance-specific option, with only 150 annotated cases public and CC-BY-NC-4.0 labeling.

None of these sources provides the 300 natural Compache conversations. Preserve official QA/evidence separately from synthetic follow-up turns and dependencies. A synthetic trace derived from a public benchmark question must never be described as an official benchmark conversation or as a measured model output.

Trace construction contract

Keep two namespaces in every row:

• benchmark_source: official benchmark_id, question_id, document_id, exact revision/commit, question, reference answer, answerability, evidence-page/paragraph metadata, source URL, and license/provenance note.

• authored_trace: generated conversation_id, turn_id, authored prompt, source insertions, retrieval result, captured assistant output, and dependency edges. Mark every authored question/dependency as synthetic. Never relabel it as official benchmark annotation.

For each selected QASPER question, preserve the question's official paper ID, extracted full text and paragraph/section boundaries. Record source URL/ID, checksums, extraction tool/version, source and dataset licenses, and configured model-tokenizer counts. For the official task, retrieve only from that paper and keep its official labels. Create a normal retrieval path that selects passages using the question and a separate oracle-evidence diagnostic using annotated evidence; do not mix oracle results into normal retrieval. The prompt receives retrieved source text, never the reference answer, evaluator notes, or hidden labels. Do not pad a short source or add unrelated papers. If an authored cross-paper question uses multiple documents, create new labels and mark the task as synthetic. Measure the actual assembled retrieval payload per run; a source document need not itself meet 15–50k tokens.

An initial trace should start with the exact official question over real document text. Later turns can ask natural follow-ups, revisions, quotations, clarifications, or cross-source synthesis, but their wording must not restate the answer-bearing facts. Store source insertion turn/page and dependency distance. The live output field must contain the actual answer produced by that run. A template answer is a gold expectation only; it is never a substitute for a generated prior answer.

Represent dependency evidence as an explicit graph with AND requirements and OR sufficient alternatives. For an authored question, every required fact node must be independently traceable to the particular earlier input/retrieved source/output that supports it. Alternative evidence bundles are OR only after a curator verifies each bundle is independently sufficient. Official evidence-page lists identify annotated evidence, but do not by themselves prove that each page is mandatory, that pages are interchangeable, or that separate listed pages form independently sufficient alternatives. Do not infer these semantics mechanically. If provenance does not establish necessity/sufficiency, label dependency candidate and omit it from strict dependency scoring.

For MuSiQue, preserve official split, question, support paragraphs and answerability/sufficiency labels; evaluate official answer and support metrics separately. Use its constructed connected hops as a dependency diagnostic, not as evidence that arbitrary authored dependencies are valid. For LongMemEval, preserve original question/history/evidence-session IDs as the benchmark unit and evaluate with the official protocol separately. If its sessions are adapted into Compache traces, keep the transformation and any inserted synthetic turns in a distinct layer. Do not claim that constructed traces are original LongMemEval examples.

Splits, licensing, and reproducibility

Freeze repository/HF dataset revisions by immutable commit and record each file checksum. The current web-visible main branch is not a reproducible pin. Split at document_id before any authored question/follow-up generation: no PDF or near-duplicate source document can appear in both tuning and final evaluation. Keep all questions from one PDF in the same partition. Report any public-test exposure as a contamination risk; public benchmark splits are not secret model holdouts.

MMLongBench upstream reports research-only / CC-BY-NC-4.0 terms; do not assume the V2 annotation repository grants rights to redistribute upstream PDFs or extracted text. FinanceBench also labels its public dataset CC-BY-NC-4.0. QASPER metadata says CC BY 4.0, and its full text is extracted from S2ORC; verify actual source-document permissions before redistributing the corpus. RAGBench's card says CC BY 4.0, but component-source terms can differ. MuSiQue repository license is CC BY 4.0; LongMemEval repository is MIT while filler sources remain separately attributable. This note is not legal advice: before shipping derived text or full benchmark records, inspect pinned artifacts and source rights. A package-friendly default should distribute generator code and source manifests/IDs/checksums, not bundle source text unless the specific source license allows it.
