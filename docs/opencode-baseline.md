# OpenCode baseline adapter

This is a Python projection of the default v1 session compaction path in OpenCode v1.19.5, commit `810c0eba1a7348036f8bdf61e6632d0c36c6876c`, not the native OpenCode executable. OpenCode is MIT licensed; the prompt template and instructions are reproduced from `packages/core/src/session/compaction.ts`, copyright OpenCode contributors. The selection and overflow logic follows `packages/opencode/src/session/compaction.ts`, `overflow.ts`, and `message-v2.ts`.

Use `prepare(request, last_completed_usage)` to obtain the actual summary prompt when overflow occurs. Run that prompt with the chosen agent, record its actual token usage, then call `complete(request, prepared, actual_summary, summary_usage)`. Include the summary call and synthetic continuation in workload and cost accounting. `project(request)` provides the projected subsequent context. The caller must supply completed-call usage; unknown usage is not zero. The `total` field takes precedence when nonzero, otherwise input, output and cache counts are summed.

Canonical sources lack OpenCode tool inputs, message structure, plugin hooks and native serialization. Each retrieval is projected as one synthetic completed `retrieval({})` tool result. The default tail token estimator uses ModelSpec's bytes-per-token approximation over simplified message JSON, not OpenCode's exact provider conversion or tokenizer; inject a counter over Message tuples to improve it. No provider overflow retry/media replay, plugin hooks, pruning, real tool schemas, hidden reasoning, or provider token accounting is simulated. Pruning defaults off in the pinned implementation. These limitations prevent claims of native execution or exact equivalence.
