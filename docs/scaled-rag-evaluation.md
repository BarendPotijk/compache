# Scaled synthetic RAG offline evaluation

Run `PYTHONPATH=src python scripts/evaluate_scaled_rag.py --dataset DATASET --policy POLICY --profile PROFILE --output OUTPUT` with the frozen policy and matching profile. It streams one compressed thread and its labels at a time, validates them through the replay contract, and writes compact per-run and per-thread records. No training, policy selection, API calls, or answer generation occurs. The policy/profile and dataset manifest hashes are recorded. Source shards carry their own hashes in the dataset manifest.

Historical coverage means complete sufficient authored source alternatives remain available before recovery; AND within an alternative, OR across alternatives. Direct lookup is excluded from the historical denominator. Unknowns and replay-skipped runs are explicit. Family, lag and position groups report counts, not inferred population rates. Admission failure terminates that thread's replay, so unassessed later runs must not be interpreted as retained. Synthetic template outputs are not model answers or answer-quality measurements.

Costs use byte-estimated token equivalents and the existing single-prefix cache simulator, with a 16,000-token modeled runtime overhead. The cache-only baseline charges the full canonical request without compaction or pings; it is not an OpenCode implementation or measured billing. The fixed policy uses a 300-second cache TTL. The observation window ends at the last recorded run; unobserved future pings are reported. Zero recovery overhead means no sources are restored, so misses remain visible and recovery cost is not estimated.

Both the cache-only full-workload cost and the cost for the prefix admitted by the frozen policy are reported. If admission fails, compare the policy cost only to the admitted-prefix baseline, and do not describe the difference against the full-workload baseline as savings. The replayed count includes the failed admission attempt, which incurs no modeled request charge.
