# Public benchmark options for long RAG and conversation memory

## Recommendation

No single public benchmark covers long multi-turn history, business-document retrieval, answer grounding, and live cache/compaction behavior. Keep the frozen custom workload as the primary paired runtime/cost test. For public quality checks, use **LongMemEval-S** for long-term conversational memory, **RAGBench** for grounded end-to-end RAG, and **BRIGHT** for reasoning-intensive retrieval. Add a small **MuSiQue** slice when testing multi-source dependency reasoning. **BEIR** is useful as a conventional retrieval sanity check; **LongBench v2** is an optional context-length stress test. These are complementary measurements, not interchangeable leaderboard scores.

| Benchmark | What it measures / scale | Labels and fit | Provenance, access, caveats |
|---|---|---|---|

Closest public match for retrieving facts from conversation history, but not static handbook RAG or cache/runtime comparison. | [Paper](https://arxiv.org/abs/2410.10813), [official repository](https://github.com/xiaowu0162/LongMemEval), [cleaned dataset](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned). Dataset card specifies CC-BY-4.0 and train/validation/test splits. Audit component-corpus provenance and terms before redistributing derived material. |

Repository identifies the data as CC-BY-4.0 and links the hosted data. Pin the dataset/repository revision and the short/long setting. |

CC-BY-4.0. The repository documents possible overlap of source questions with model pretraining and supplies leakage information; use a frozen test split and report that limitation. |
| **BEIR** | Heterogeneous zero-shot IR suite; 18 datasets in the paper and 15+ in the maintained toolkit. | Query-document relevance labels and standard IR metrics. ## Other credible options

- **QASPER** is a useful long-document evidence benchmark: 5,049 questions over 1,585 NLP papers, with evidence that can be paragraphs, tables, or figures; the paper reports that many answers require multiple paragraphs. It is narrower than the proposed stack and requires per-paper provenance/rights review. Sources: [NAACL paper](https://aclanthology.org/2021.naacl-main.365/), [official baseline repository](https://github.com/allenai/qasper-led-baseline).
- **HotpotQA** provides 113k Wikipedia multi-hop questions with sentence-level supporting facts. It is a good easier multi-hop/support-fact comparator, while MuSiQue is a better fit when connected evidence dependencies and reduced shortcut opportunities matter. Sources: [EMNLP paper](https://aclanthology.org/D18-1259/), [official site and data](https://hotpotqa.github.io/). The official site states CC BY-SA 4.0.

## Suggested evaluation stack

1. **Primary systems result:** run Compache and OpenCode against the same frozen custom conversation and retrieved source bundle. Report answer quality, evidence support, actual context/token usage, compaction events, and runtime/cost separately. Public benchmarks do not establish this paired live-system result.
2. **Memory generalization:** run LongMemEval-S with the official evaluator and gold-session retrieval recall. This tests a different, public history distribution.
3. **Grounded RAG quality:** evaluate a frozen RAGBench test slice, retaining its support/adherence labels. Use BRIGHT separately if the question is specifically whether retrieval ranking improves.
4. **Dependency check:** add a modest MuSiQue test slice and report answer F1 plus support F1. Use BEIR only as a small, standard retriever sanity check; use LongBench v2 only for a separate long-context sweep.

Freeze dataset revisions, IDs, retrieval configuration, prompt, model/version, decoding, and grader before the held-out runs. Tune only on validation data. Do not claim a public rank unless the full official protocol is matched; do not combine public task scores with the custom runtime result into one score. Public test questions may have appeared in model training, so these datasets are external validation, not guaranteed pristine model holdouts.
